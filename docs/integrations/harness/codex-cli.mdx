The NVIDIA NeMo Fabric `nvidia.fabric.codex.cli` adapter runs the Codex
command-line interface (`codex exec --json`) directly, without the Codex Python
SDK. Each invocation executes one non-interactive Codex turn; later turns of
the same runtime resume the same Codex thread with `codex exec resume`.

Use this adapter when the execution environment provides a managed `codex`
executable. For SDK-managed execution with MCP, skills, and structured
instructions, use the [`nvidia.fabric.codex` adapter](codex.mdx).

## Install the Adapter

To install the NeMo Fabric runtime and the adapter in one environment:

```bash
pip install "nemo-fabric[codex-cli]"
```

To install only the adapter:

```bash
pip install nemo-fabric-adapters-codex-cli
```

The harness is the external `codex` executable; install the Codex CLI
separately and keep it on `PATH`. The adapter's `harness` and `full` extras
install no additional packages. `doctor(...)` reports whether the `codex`
binary is available.

For separate runtime and adapter environments, set `ADAPTER_PYTHON` in the
runtime environment to the adapter environment's Python interpreter and use
matching NeMo Fabric release versions.

## Configure the Adapter

Select the Codex CLI harness integration in `HarnessConfig`:

```python
from nemo_fabric import HarnessConfig

harness = HarnessConfig(adapter_id="nvidia.fabric.codex.cli")
```

The adapter accepts the normalized `models` and `models.base_url` fields. The
`openai` provider uses Codex's native credential resolution, including a cached
`codex login`; another provider name requires an OpenAI Responses-compatible
`base_url` and `api_key_env`.

The descriptor validates the following `harness.settings` fields:

| Setting | Type | Default | Description |
| --- | --- | --- | --- |
| `sandbox` | string | `read-only` | Codex filesystem access level: `read-only`, `workspace-write`, or `danger-full-access`. |
| `skip_git_repo_check` | boolean | `false` | Allows Codex to run outside a Git repository. |
| `config_overrides` | object | `{}` | Dotted Codex configuration keys merged into the generated, runtime-scoped Codex profile. |

## Understand the Runtime Lifecycle

Each NeMo Fabric runtime tracks one Codex thread. Runtime-scoped configuration,
including model providers and telemetry, is written to a generated Codex
profile (`$CODEX_HOME/fabric-<runtime>.config.toml`) that is removed when the
runtime stops. When NeMo Relay telemetry is enabled, the adapter starts the
Relay gateway, routes model traffic through it, enables Codex hooks that
forward events to NeMo Relay, and finalizes Agent Trajectory Observability
Format (ATOF) and Agent Trajectory Interchange Format (ATIF) artifacts after
each completed invocation.

For the complete configuration and lifecycle reference, refer to the
[Codex CLI adapter guide](https://github.com/NVIDIA/NeMo-Fabric/tree/main/adapters/codex-cli).
